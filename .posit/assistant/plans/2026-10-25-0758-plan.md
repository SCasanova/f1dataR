# Plan: Issue #303 - F1 timing requires authentication

## Background
Since 2026-10-15 F1 live timing (used via FastF1) needs an F1 account. FastF1 reads `F1_USERNAME` and
`F1_PASSWORD` from the environment (password method). Tokens last 4 days and FastF1 re-logs in
automatically when credentials are in the environment. Without credentials FastF1 can't prompt through
reticulate, so f1dataR must handle it on the R side.

Agreed approach: f1dataR checks that the env vars are set (not that they are valid). If set, proceed. If not
and `interactive()`, prompt via `set_f1_auth()`. Otherwise fail with a clear error.

## Decisions (from user)
- Prompting uses `askpass` (R side).
- Browser auth method is not supported; password method only.
- `set_f1_auth()` writes the values to an environment variable file that R picks up (`~/.Renviron`), and also sets them for the current session.
- Minor version release (bump the minor number, with a NEWS entry).
- Always run the check. The memoised/cached function returns the stored result, so the check sits in the uncached code path and is always evaluated before a FastF1 call.

## Where to hook in
All FastF1 sessions go through `get_session()` (R/plotting_style.R:494) and `load_race_session()`
(R/load_race_session.R:39). `load_session_laps()`, `load_driver_telemetry()` and the plotting helpers call
these. Add `check_ff1_auth()` right after `check_ff1_version()` in both. Check `circuit_details()` (calls
`check_ff1_version()` at R/circuit_details.R:36) and add it only if it reaches live timing.

## Changes
1. **New `R/auth.R`**
   - `check_ff1_auth()` (internal): invisibly TRUE if `F1_USERNAME` and `F1_PASSWORD` are both non-empty.
     Otherwise, if `interactive()`, call `set_f1_auth()`; if not, `cli::cli_abort()` naming the two
     variables and pointing to `set_f1_auth()` and the FastF1 auth docs.
   - `set_f1_auth(username = NULL, password = NULL, persist = TRUE)` (exported):
     - Missing username: `readline()`-style prompt; missing password: `askpass::askpass()` (no echo).
       Abort in non-interactive use if values aren't supplied.
     - `Sys.setenv()` for the current session (FastF1 sees it since reticulate shares the process).
     - If `persist = TRUE`: upsert `F1_USERNAME` / `F1_PASSWORD` lines in `~/.Renviron` (respect
       `R_ENVIRON_USER` / `usethis`-style location), replacing existing entries, preserving other lines,
       and setting file mode 0600 where supported. Ask for confirmation interactively before writing, since
       this stores a plaintext password; mention this in the docs. Tell the user it applies to future sessions.
     - Never print or log the password.
2. **Wire in** `check_ff1_auth()` in `get_session()` and `load_race_session()`.
3. **DESCRIPTION/NAMESPACE/docs**: add `askpass` to Imports (or Suggests with `rlang::check_installed()`; default
   to Imports so the prompt always works); bump minor version; `devtools::document()`; add to `_pkgdown.yml`
   reference index if it lists functions.
4. **Narrative docs**: "Authentication" section in README and relevant vignette(s); NEWS.md entry under the new minor version.
5. **Network check**: `check_ff1_network_connection()` uses `req_error(is_error = ~FALSE)`, so a 401/403 counts as
   connected. Leave as is; document the limitation.

## Tests (testthat)
- `check_ff1_auth()` with `withr::local_envvar()`:
  - both set -> TRUE
  - one missing / empty -> error (non-interactive) mentioning `F1_USERNAME`/`F1_PASSWORD`
  - none set, interactive (mock `rlang::is_interactive`) -> `set_f1_auth` called
- `set_f1_auth()`: with supplied args and a temp `R_ENVIRON_USER`, writes/upserts lines correctly, preserves
  other lines, is idempotent, does not write when `persist = FALSE`, mock `askpass::askpass` for the prompt path.
- Existing vcr/httptest2 tests: set dummy credentials in `tests/testthat/setup.R` (`withr::local_envvar`) so
  cassettes keep working. Live FastF1 tests skip when no real credentials (`skip_if_no_f1_auth()` helper).

## Remaining caveat
Storing a plaintext password in `~/.Renviron` is the cost of the chosen design; documentation should note it
and suggest a keyring/secrets manager as an alternative for shared machines.
